# Slice 17 — KB Markdown export

## Goal

`python -m cartograph.kb.export --repo NAME` renders published knowledge-base entries into Markdown a consumer repo can read with Cartograph switched off: all glossary terms into one root `CONTEXT.md`, each decision into `docs/adr/NNNN-slug.md`, each specification, convention and runbook into its own file. Postgres stays the source of truth — the export is strictly one-way — so the job's real work is being deterministic enough to commit and cautious enough never to overwrite something a human wrote.

## Depends on

Slice 15 (`KbType.export`, `KbType.sort_key`, `ExportContext`, `entries_for_export`). Slice 16 only for the statuses it filters on.

## Spec references

`specs/README.md` global conventions: "batch jobs are CLI modules, not long-lived workers". Copy the CLI shape from `backend/src/cartograph/enrich/__main__.py` — argparse in `__main__.py`, an argv-free `run_export` in `runner.py`, `traceback.print_exc()` on an unhandled exception, a JSON summary on stdout.

## Requirements

### 1. Package — `cartograph/kb/export/`

```
__init__.py
__main__.py     argparse + amain/main, mirroring enrich/__main__.py exactly
runner.py       run_export(session, repo, out, opts) -> ExportResult   (no argv; testable)
manifest.py     read / write / hash .cartograph-manifest.json
```

Invocation follows the project convention:

```sh
docker compose run api uv run python -m cartograph.kb.export --repo acme
```

| flag | default | meaning |
|---|---|---|
| `--repo NAME` | required | repository name; unknown → exit 2 |
| `--out PATH` | `repository.root_path` | target directory. **No new compose config** — this is the same mount `ingest register --root` already requires |
| `--type NAME` | all registered | repeatable |
| `--no-include-global` | off | exclude `repository_id IS NULL` entries |
| `--dry-run` | off | print the plan and the exit code it *would* return; write nothing |
| `--force` | off | overwrite conflicts |
| `--no-prune` | off | keep files whose entries no longer export |
| `--context-name` | the repo name | the `# H1` at the top of CONTEXT.md |
| `--context-description` | empty | one line under that H1 |

There is deliberately **no `--json`**: the summary is always JSON on stdout, matching `python -m cartograph.enrich`. A flag selecting the only behaviour there is would be a lie.

Exit codes follow the project contract:

| code | meaning |
|---|---|
| 0 | clean — everything written or already up to date, no conflicts |
| 1 | unhandled exception, traceback printed |
| 2 | unknown repository, or `--out` missing / not a directory |
| 3 | partial — ≥1 conflict skipped or ≥1 entry failed to render. Re-run to retry |

### 2. Determinism

Re-exporting with no database change **must produce byte-identical files**, because these files get committed and a spurious diff on every run destroys their usefulness.

1. Rows come from `entries_for_export` ordered `lower(title), (repository_id IS NULL), slug, id` — the NULL-scope key is what makes a repo-scoped entry shadow a global one — then stable-sorted by `KbType.sort_key`, so the SQL order is the tie-break.
2. **No timestamp, run id, hostname or absolute path appears in any rendered byte.** An ADR's `Date:` line comes from `payload.date` or `created_at.date()` — a date, not a wall clock.
3. LF endings, exactly one trailing newline per file.

### 3. Rendering

`run_export` builds one `ExportContext` per run: `repository_name` from the `Repository` row, and `context_name`/`context_description` from the two CLI flags above — the H1 and its blurb are editorial and the model has no column for them. `marker` is a method on the context, not a field. It then calls each type's `export(entries, ctx)` and merges the returned `dict[PurePosixPath, str]`.

Every generated file opens with:

```
<!-- generated by cartograph; edits will be overwritten. source: kb <type>/<slug> -->
```

Paths returned by a type are always relative and must never contain `..` — slice 15's import-time self-check covers `export_dir`, but `run_export` re-checks each returned path before touching the filesystem, because a path is data and the check is one line.

### 4. Clobber safety

A manifest at `<out>/.cartograph-manifest.json`:

```json
{"version": 1, "repository": "acme", "files": {
  "CONTEXT.md": {"sha256": "…", "type": "glossary"},
  "docs/adr/0001-use-postgres.md": {"sha256": "…", "type": "decision"}}}
```

No `slug` field: a glossary artifact renders every glossary entry into one file
and has no single slug to record, so path plus type is the whole identity.

**Manifest keys are repo content, and therefore untrusted.** An absolute key
escapes `out / key` entirely and `..` walks out of it — so the prune path
re-checks every key for both before touching the filesystem. That check matters
more there than anywhere else in this job, because pruning *deletes*.

It is also written on **every** non-dry run, not only when something changed:
gating it on written-or-pruned meant a deleted manifest was never rebuilt, which
silently disabled case 2 below and let the case-3 marker fallback overwrite hand
edits forever.

Exactly three cases per target path:

1. **Absent on disk** → write, record.
2. **Present and in the manifest** → compare the on-disk sha256 to the recorded one. Match, or the file already equals the newly rendered bytes → write/skip and record. **Mismatch** → it was hand-edited since we wrote it → **skip, report `conflict`**. The manifest is authoritative here and the marker must NOT rescue this case: our own header survives a hand edit, so trusting it would discard one.
   A target that cannot be read as UTF-8 (binary, wrong encoding, a directory) is treated the same way — reported as a conflict, never touched, and never allowed to abort a run that has already written other files.
3. **Present but not in the manifest** → we have never written it, so it is hand-authored → **skip, report `conflict`**. *Escape hatch:* if the first line is our marker, treat it as ours — this covers a lost or deleted manifest.

`--force` overrides cases 2 and 3 — **and the prune path too**. The CLI tells the operator to re-run with it, so it has to work for the case it prints it on.

**Case 3 is what protects a hand-written root `CONTEXT.md`.** It refuses on the very first run, loudly, with exit 3 — it never silently clobbers, and the failure is legible enough that the operator knows to move their file or pass `--force`.

Pruning: manifest paths this run no longer produces (entry archived, deleted, or retyped) are deleted **only if** the on-disk hash still matches the manifest; otherwise report `conflict` and leave the file alone. `--no-prune` skips this entirely.

### 5. Partial tolerance

Render everything into memory first, then write each file temp-file + `os.replace` in the same directory, so no target is ever half-written. An entry whose `payload` no longer validates against its type is counted into `failed` and skipped while every good file still lands — the same philosophy as `enrich`'s commit-per-batch, and the reason exit 3 means "re-run to retry" rather than "nothing happened".

Summary on stdout:

```json
{"repo": "acme", "written": 12, "unchanged": 30, "pruned": 1,
 "conflicts": ["CONTEXT.md"], "failed": [{"slug": "x", "error": "…"}],
 "warnings": ["glossary: 187 terms in one CONTEXT.md"], "dry_run": false}
```

Warnings come from `KbType.validate_entry` (the non-fatal lint) plus a CLI-level warning above 150 glossary terms — one root `CONTEXT.md` is designed for a curated list, and a bloated one is the reference model's most-reported failure. If it becomes a real problem the escape hatch is a `--split-glossary` writing `docs/glossary/{letter}.md`, which is a `Glossary.export` change only and needs no schema work.

### 6. Documentation

`README.md` gains an export section next to the enrichment one: the command, that Postgres is the source of truth and the Markdown is a copy, that a hand-written file is refused rather than overwritten, and that re-running is safe and produces no diff. State plainly that **editing an exported file changes nothing** and the next export will not read it back.

## Acceptance criteria

1. `--repo nonexistent` exits 2; a missing `--out` directory exits 2.
2. Against a seeded repo, the run writes `CONTEXT.md` in the reference format (`## Language`, `**Term**:`, `_Avoid_:` omitted when empty) plus `docs/adr/0001-*.md`, `docs/spec/*.md`, `docs/convention/*.md`, `docs/runbook/*.md`.
3. **Byte-identical re-run** — run twice with no DB change, assert every file's bytes are unchanged and the second summary reports `written: 0` with everything in `unchanged`.
4. A hand-written `CONTEXT.md` present before the first run is **not** overwritten: the file is untouched, `conflicts` names it, exit is 3. With `--force`, it is overwritten and exit is 0.
5. Editing a previously generated file and re-running detects the manual edit via the manifest hash and skips it with exit 3.
6. Archiving an entry prunes its file — unless that file was edited, in which case it is left and reported as a conflict.
7. `--dry-run` writes nothing, creates no manifest, and reports the exit code it would have returned.
8. `proposed`, `rejected` and `archived` entries never appear in any output.
9. Global entries are included by default and excluded with `--no-include-global`; a repo-scoped entry **shadows** a global of the same title, so the term appears exactly once in `CONTEXT.md`.
10. `--type glossary` writes only `CONTEXT.md` and prunes nothing belonging to other types.
11. One entry with a payload that fails its type's model exits 3, names the slug in `failed`, and every other file is still written.
12. `cd backend && uv run pytest tests/kb/` fully green.

## Out of scope

- Reading Markdown back into the database. The export is one-way by design; a half round-trip is worse than none.
- Committing or pushing the exported files — the CLI writes a working tree and stops.
- Any git-hook integration (a follow-up if it earns its keep; the post-commit hook in slice 14 is the precedent).
- `--split-glossary` (§5 records the trigger).
- Any SPA affordance for triggering an export (slice 18 does not add one).
