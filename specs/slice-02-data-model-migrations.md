# Slice 02 — Data model & Alembic migrations

## Goal

The complete SQLAlchemy 2.0 data model exists in `codegraph/models.py`, Alembic is wired for async migrations, and one initial migration creates the extensions, enums, tables, and every index — including the ones autogenerate cannot produce. `docker compose up` now runs `alembic upgrade head` for real on api startup.

## Depends on

Slice 01.

## Spec references

`initial-spec.md` §4 (data model — the models below are that code with corrections), §8 (ingest_runs).

## Requirements

### 1. Models — `src/codegraph/models.py`

Use the spec §4 model code **verbatim**, with these deliberate corrections and additions (the spec has known errata):

1. **Missing import:** add `from sqlalchemy.dialects.postgresql import JSONB` (spec uses `JSONB` in `Agent.metadata_json` without importing it).
2. **Add `summary_source_hash` to `Node`** (`Mapped[Optional[str]]`, Text): records the `content_hash` the tier-3 summary was generated from, so slice 13 can skip unchanged nodes without a schema change later.
3. **Add the `IngestRun` model** (spec §8 mentions the table but doesn't model it):

```python
class IngestRun(Base):
    __tablename__ = "ingest_runs"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    repository_id: Mapped[int] = mapped_column(
        ForeignKey("repositories.id", ondelete="CASCADE"), index=True
    )
    trigger: Mapped[str] = mapped_column(Text, default="manual")  # manual | hook | ci
    status: Mapped[str] = mapped_column(Text, default="running")  # running | succeeded | failed
    started_at: Mapped[datetime.datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now()
    )
    finished_at: Mapped[Optional[datetime.datetime]] = mapped_column(DateTime(timezone=True))
    stats: Mapped[Optional[dict]] = mapped_column(JSONB)  # per-phase timings, node/edge deltas
    error: Mapped[Optional[str]] = mapped_column(Text)
```

Everything else — `EMBED_DIM = 1024`, `Base`, `NodeKind`, `EdgeRel`, `EdgeConfidence`, `Repository`, `Node`, `Edge`, `Community`, `CommunityEdge`, `Agent`, `AgentMessage`, `KnowledgeEntry`, all `__table_args__` — exactly as in spec §4. Do not rename anything.

### 2. Engine & session — `src/codegraph/db.py`

Async engine from `Settings.DATABASE_URL` (asyncpg), `async_sessionmaker[AsyncSession]`, and a FastAPI dependency `get_session()` yielding a session per request. Pool pre-ping on.

### 3. Alembic — `backend/alembic/`

1. Async template (`alembic init -t async`), `alembic.ini` at `backend/alembic.ini`, `env.py` reading the URL from `codegraph.config.Settings` (env var wins over ini) and using `codegraph.models.Base.metadata` as target metadata.
2. **One initial migration**, autogenerated then hand-edited. Autogenerate will NOT produce these — add them manually:
   - `op.execute("CREATE EXTENSION IF NOT EXISTS vector")` and `op.execute("CREATE EXTENSION IF NOT EXISTS pg_trgm")` as the first operations, before any `create_table`.
   - The functional unique index on the KB: `op.create_index("ix_kb_term_lower", "knowledge_base", [sa.text("lower(term)")], unique=True)` — autogenerate renders `func.lower(text("term"))` incorrectly or drops it; verify the emitted SQL is `CREATE UNIQUE INDEX ix_kb_term_lower ON knowledge_base (lower(term))`.
   - Verify the HNSW indexes carry `postgresql_using="hnsw"` and `postgresql_ops={"embedding": "vector_cosine_ops"}`, and the trigram indexes carry `postgresql_using="gin"` with `gin_trgm_ops`. If autogenerate mangles them, write the `op.create_index` calls by hand.
   - The descending expression index `ix_nodes_pagerank` on `pagerank DESC`.
   - `downgrade()` must drop everything including the enums (`sa.Enum(..., name="node_kind").drop(op.get_bind())` etc.); dropping the extensions in downgrade is optional.
3. Remove the `|| true` from the api entrypoint (slice 01 scaffolding): startup is now `alembic upgrade head && uvicorn ...`, and a migration failure fails the container.

### 4. Dependencies

Add to `pyproject.toml`: `sqlalchemy[asyncio]>=2.0.40`, `asyncpg`, `alembic`, `pgvector`. Re-lock.

## Acceptance criteria

1. Fresh db (`docker compose down -v && docker compose up --build -d`): api comes up healthy, meaning `alembic upgrade head` succeeded on an empty database.
2. `docker compose exec db psql -U codegraph -c "\dx"` lists `vector` and `pg_trgm`.
3. `docker compose exec db psql -U codegraph -c "\d nodes"` shows `ix_nodes_embedding_hnsw` (hnsw), both trigram GIN indexes, and the unique constraint on `(repository_id, qualified_name, kind)`; `\d knowledge_base` shows the unique `lower(term)` index.
4. `docker compose run --rm api uv run alembic downgrade base` succeeds, then `upgrade head` succeeds again (round-trip).
5. `uv run pytest tests/test_models_roundtrip.py` passes: for each model, insert a row (including a `Node` with a 1024-dim embedding and an `Agent` with `metadata_json`), flush, read it back. Conftest provides an async session against a test database and rolls back per test.

## Out of scope

- The related-KB / search SQL — this slice is schema only.
- `summary_source_hash` population (slice 13 writes it).
